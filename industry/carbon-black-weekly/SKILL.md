# 炭黑周观察 · 制作流程

## 何时使用

- 制作或更新《炭黑周观察》（每周一期）
- 需要炭黑/煤焦油的价格走势、比值、涨跌幅等分析
- 需要"用数据讲判断"的产业链内容（不限于周报）
- 用户问「煤焦油和炭黑的价格关系」「炭黑为什么涨/跌」「这个价格合理吗」

**不适用（转用其他 Skill）**：

- 估算某个 rCB 报价是否合理 → 用 `rcb-price-reference`
- 判断 rCB 能否替代某牌号 → 用 `rcb-substitution-assessment`
- rCB 出口合规 → 用 `rcb-export-compliance`
- 识别某个炭黑样品属于哪个牌号 → 用 `rcb-grade-identification`

## ⛔ 三条铁律（违反则整篇不可信）

### 铁律 1：不给报价，只给判断

**不发布具体成交报价。** 原因有二：一是合规（避免商业数据转载风险），二是差异化（报价是商品，谁都能卖；判断才是能力）。

**可以做**：引用协会/公开资讯的价格变动，做趋势与机制分析。

### 铁律 2：口径必须写明

**同一周，不同口径会给出不同方向。** 实测过的例子（2026-10-16）：

| 口径 | 数据 | 方向 |
| --- | --- | --- |
| 日度环比（隆众日评） | 涨跌值 0 | 持平 |
| 周度对比（协会周报 vs 当日） | N330 9600 → 9500 | **降 100** |
| 资讯标题 | 「新单挺价」「上涨预期」 | **看涨** |

**三个口径，三个方向。** 所以：

- 引用价格必须写明：**日度还是周度？报价还是成交？均价还是主流价？**
- **不同口径不能混用**
- **口径不一致时，不要硬下结论 —— "信号分歧"本身就是最有价值的观察**

### 铁律 3：数据不编，判断与事实分开写

- 每个数字必须有来源（机构名 + 日期）
- **自己的判断单独标「我的判断」**，不与事实混写
- 拿不到的数据就写"未取到"，**不推测**

## 执行流程（六步）

### 第 1 步 · 更新价格序列

```powershell
node 07-头条自动化\fetch_cria_weekly.js 20
```

抓取分会周报，构建 `炭黑周观察\价格序列.json`（约 20 周）。

**⚠ 已知坑**：
- 列表页分 3 页，每页 20 条，共 41 期
- 表格解析里，**「炭黑」大类的判断必须先于字段名匹配**，否则 N330/N550/N660 全被认成 N220
- 字段名是「**改性**沥青」，不是「改质沥青」
- 跨年标题（如"12月29日~1月4日"）会被误标成年份，产出异常期，**需剔除**

### 第 2 步 · 抓行业数据（月度）

```powershell
node 07-头条自动化\fetch_cria_data.js
```

抓「重点企业统计数据」（产量、亏损面）和「焦化产品平均价格」。

### 第 3 步 · 算结论指标

```powershell
python 07-头条自动化\analyze_series.py
```

输出：涨跌幅、涨速/跌速、历史区间与当前分位、比值区间与修复空间。

**这一步是"用数据讲判断"的核心** —— 单看"涨了跌了"没有价值，要算出：
- **涨跌对称性**（涨了几周 vs 跌了几周）
- **当前分位**（在历史区间的位置）
- **比值修复空间**（乐观/中性情形下能涨多少）

### 第 4 步 · 出图

```powershell
python 07-头条自动化\make_chart.py <图表配置.json>        # 折线图
python 07-头条自动化\make_data_card.py <图表配置.json>    # 数据卡片
```

**标准图表组（6 张）**：

| 图 | 类型 | 回答什么问题 |
| --- | --- | --- |
| 图0 | 数据卡片 | 本周总览：四个方向的关键数据 |
| 图1 | 双线折线 | 原料 vs 产品走势 |
| 图2 | 单线折线 | ⭐ **比值**（成本转嫁能力）—— 这是本栏目的招牌 |
| 图3 | 数据卡片 | 企业端：产量 vs 亏损 |
| 图4 | 多线折线 | 各牌号是否分化 |
| 图5 | 数据卡片 | 下周观察清单 |

**版式规范**见 `references/chart-spec.md`。

### 第 5 步 · 写稿

**结构（先图后判断）**：

```
开篇：一句话结论（不铺垫）
   ↓ 图0 总览
第一节 价格发生了什么        → 图1 + 图4
第二节 关键指标（比值）      → 图2
一点五 把数据再算一层        → 算出 2-3 个"数字结论"
第三节 企业端印证            → 图3
第四节 为什么会这样（机制）
第五节 下周看什么            → 图5
第六节 我的判断
```

**写作要求**：
- **开头第一句必须是结论或反常识**，不写"本周市场如何如何"
- **每个小节先给数据，再给判断**
- **判断要和主流说法有区别**（同行只报数字，我们给机制）
- 结尾签名固定：**「我们不给报价，只给判断——以及接下来该看什么。」**

### 第 6 步 · 推送草稿箱

```powershell
python 05-脚本\md2wechat.py 02-草稿\<稿件>.md --push
```

- 稿件需带 frontmatter（title / digest / cover / author / footer / sources / question）
- 本地图片会自动上传微信图床
- **推完检查文风体检警告**（禁用词、程度词、数字密度）
- **若有多版，删掉旧版**：

```powershell
python 05-脚本\connect.py --drafts                       # 列出
python 05-脚本\connect.py --delete-draft <media_id>      # 删除（不可逆）
```

## 常见坑（踩过的）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| **炭黑牌号解析** | N330/N550/N660 全被认成 N220 | 先判断「炭黑」大类，再读下一行的牌号 |
| **跨年标题** | 出现 `2026-12-29` 这种异常期 | 剔除，或从标题里提取年份 |
| **折线图小数刻度** | 比值 1.67~1.86 的 Y 轴全变成"2" | 数值跨度 < 20 时用 2 位小数 |
| **X 轴标签重叠** | 末尾两个日期叠在一起 | 自适应步长，按标签实际宽度算 |
| **页脚压字** | 来源文字盖住署名 | 来源过长时自动截断加省略号 |
| **文中用 markdown** | 头条/微信不渲染 `**粗体**`，原样显示星号 | 只写纯文本，或用 `md2wechat` 的清洗 |
| **口径混用** | 用日度数据得出周度结论 | 铁律 2：写明口径、不混用 |

## ⛔ 铁律 4：公众号配图不要署名水印

**公众号的图，右下角不出现「老赵产业观察」。** 原因：水印会让图表显得像自媒体搬运，削弱"专业媒体"的观感。

**实现方式**：图表配置里**不写 `author` 字段**，就不画署名（`make_chart.py` / `make_data_card.py` 均已把默认值改为空）。

| 平台 | 署名 | 做法 |
| --- | --- | --- |
| **微信公众号（炭黑周观察）** | **不画** | 配置里不写 `author` |
| 今日头条（微头条 / 长文章） | 画 | 配置里显式写 `"author": "老赵产业观察"` |

**对比**：公众号图 = 标题 + 数据 + 来源（干净权威）；头条图 = 加上署名（引流账号要品牌曝光）。

⚠ `make_data_card.py` 曾把署名写进默认值，导致不写也会画。**现已改为空默认值**，别再改回去。

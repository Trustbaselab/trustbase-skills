# rCB 替代可行性评估

## 何时使用

用户出现以下意图时触发：

- 给出一组 rCB 实测参数（碘值 / BET / DBP / 灰分 / 甲苯透光率），问能用在哪里
- 询问某个原生牌号（N550 / N330 / N660 / N772…）能否被 rCB 替代
- 询问替代比例或掺配上限
- 比较 rCB 与原生炭黑的经济性

**不适用（转用其他 Skill）**：

- 问 rCB 价格或指数 → 用 `rcb-price-reference`
- 问出口欧盟要什么认证 → 用 `rcb-export-compliance`
- 只给一组参数问「这属于什么材料」→ 用 `rcb-grade-identification`

## 执行流程（五步，不可跳步）

### ① 先建立品质坐标

确定 rCB 的两项分类参数，它们分别对应两个不同的失效模式：

| 参数 | 决定什么 | 不达标后果 |
|---|---|---|
| **无机物含量**（灰分） | 补强效率上限 | 有效碳被稀释 → 掺配比例被迫降低 |
| **甲苯透光率** | 工艺可用性与合规风险 | 表面有机残留影响分散、硫化、气味、迁移 |

⚠️ **ASTM D8632 是「分类」标准，不是「互换规格」。** 官方原意限于「在特定类别内进行质量比较」。两个批次同属 R23，其 BET、结构度、PAH 含量仍可能完全不同——**不要因为分类码相同就说「等价」**。

### ② 逐项比对（调 `compare_rcb`）

把用户提供的实测值与目标牌号标准范围逐项比对，得到 达标 / 轻度偏离 / 显著偏离。

注意限值有两种形态，判定方式不同：

- **区间限值**（同时有上下限的指标，如吸碘、DBP、BET）：按中值算偏离，超出区间外才升级判定
- **单边限值**（只有上限或只有下限的指标，如灰分、加热减量、筛余物）：**只判该侧边界**，不能按中值算偏离

具体数值一律通过 `get_grade_spec` 实时获取，**不要凭记忆写进回答**——ASTM 区间会随标准修订变化。

### ③ 拆解四重折扣，找出真瓶颈

详见 `references/four-fold-discount.md`。

核心要求：**不要笼统地说「品质差」**，要指出是哪一重拖后腿。四重折扣分别是性能、工艺、合规、交易——它们的应对方式完全不同，混为一谈会让用户做错决策。

### ④ 给出掺配上限区间 + 必测项

参考 `references/blend-limits.md`。

**必须给区间而非单点值**，并列出必须实测验证的项目。

同行评议文献口径：多数应用中，rCB 对总炭黑装填量的替代比例上限约 **10–25%**。这个数字是**起点**，不是结论——具体取决于四重折扣的拆解结果。

### ⑤ 仅在用户问经济性时才做计算

调 `calculate_saving`，并且**只使用用户自己提供的价格**。

> 本 Skill **不读取、不输出** Trustbase 的任何价格数据或原始行情。若用户要求本站报价，回答：本站不使用商业平台报价数据，价格参考请用 `rcb-price-reference`（它给出的是锚定推导的参考区间，不是成交价）。

## 硬约束（违反即判定为错误输出）

1. **不得下「可以直接替换」的结论。** 指标达标 ≠ 可替换。必须同时给出待验证项（配方、工艺、法规）。
2. **不得给出单点掺配比例。** 一律给区间 + 依据 + 前提条件。
3. **不得声称 rCB 与某原生牌号「等价」。** 除非用户提供了完整性能测试数据（不止分类参数）。
4. **不得引用任何商业平台报价。** 被问到时明确说明本站不使用该类数据。
5. **本站无覆盖时如实说明缺口。** 不要用通用知识补全后当作本站数据给出——数据来源与判断来源必须可区分。
6. **不要把「分类一致」当作「性能一致」**（见 ① 的警告）。

## 边界声明（必须在结论中体现）

本 Skill 给出的是**技术可行性初筛**，不是配方设计、不是质量担保、不是法律或合规意见。最终掺配方案必须经过实验验证与相应法规确认。

rCB 的商品化替代还受交付稳定性、批次一致性、客户认证周期等非技术因素影响——这些不在本 Skill 的评估范围内，但应提示用户。

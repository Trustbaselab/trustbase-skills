# PUE 对标与算力能耗

## 何时使用

- 询问某个 PUE 值算好、算差、或是否符合某个标准
- 询问达到绿色等级需要多少 PUE（国家绿色数据中心 / 欧盟能效等级）
- 询问算力设施耗多少电、电费大概多少
- 询问数据中心怎么采购绿电
- 询问某算力集群或枢纽的规模

**不适用（转用其他 Skill）**：

- 问设施的碳排放核算 → `carbon-cbam-cost-calc`
- 问 rCB / 炭黑 → 任一 `rcb-*` 技能

---

## ⚠️ 三个最常被混淆的口径

本领域的 PUE 数字几乎从来不可直接比较，因为**口径**不同。判断错了口径，结论必然错。

| 口径问题 | 为什么重要 |
|---|---|
| **年均值 vs 设计值** | 设计 1.2 与年均 1.2 是完全不同的成就。设计值是承诺，年均值是实测。 |
| **满载 vs 部分负载** | PUE 随负载变化。30% IT 负载测的数字与 80% 负载测的数字不可比。 |
| **全设施 vs 仅 IT 边界** | 冷却塔、办公区、变电站损耗算不算在内，会显著改变数字。 |

**规则：对标任何 PUE 之前，先确认这个数字是什么口径。** 用户不清楚时，说清楚，并把基准呈现为区间加口径提示，而不是给一个单一的合格/不合格判定。

## 执行流程（四步，不得跳步）

### ① 先确认用户那个数字的口径

做任何比较之前，先弄清：

```
· 这个数是年均值，还是设计值？
· 在什么 IT 负载率下测的？
· 边界含什么（只有冷却？含变电站？含办公）？
· 是单次测量，还是经过认证的年度数据？
```

**任何一项不清楚，就要明确说出来。不许拿着一个没定口径的数字直接下合格/不合格判定。**

### ② 取基准区间，不是取阈值

调用 `get_pue_benchmarks`。数据库通常提供三类数字：

```
· 全国/区域平均值（带它所指的设施类别）
· 绿色等级阈值（例如欧盟 A–G 能效评级）
· 具名标杆设施（个案数字，不是类别基准）
```

**必须在回答里区分这三类：**

| 数字类型 | 该怎么用 |
|---|---|
| 某界定类别的平均值 | 只能和同类设施比较 |
| 绿色等级阈值 | 说明阈值和它所属的评级体系 |
| 单个标杆设施 | 作为个案呈现，明确写「不构成类别基准」 |

**绝不许拿用户的设施去跟一个标杆个案比，然后把个案说成基准。**

### ③ 只有在用户提供输入时才做能耗与成本计算

调用 `calculate_compute_energy_cost`，需要：

```
· IT 功率（kW）—— 用户提供，或由机架数 × 单机架功率密度推算
· PUE —— 用户自己的数字
· 小时数 —— 用户提供；若做年度估算则用 8760
· 电价 —— 用户提供
```

**用户没有电价，就明确说这是缺失输入。不许拿一个市场均价替代后当成他的成本。**

### ④ 说清不算的部分

结尾必须交代：这是算术估算，不是电费账单。需量电费、分时电价结构、冷却水成本、绿证成本都不在本计算范围内。

## 硬约束（违反即判定为错误输出）

1. **不许对没定口径的 PUE 做对标。** 先定口径（年均/设计、负载率、边界）。
2. **不许给一个不带评级体系的 PUE 阈值。**「PUE 必须低于 1.3」不说清哪个标准、哪一年、哪类设施，就是无意义的。
3. **不许拿标杆个案当类别基准。** 个案是个案。
4. **不许编造电价。** 用户没有就说是缺失输入。
5. **不许把能耗成本结果说成电费账单。** 它是对用户输入的算术。
6. **引用 `get_power_consumption_stats` 时必须区分两种官方口径。** 工具并列返回两种口径，二者不可互换。
7. **本站无覆盖时如实说明缺口。**

## 边界声明

本 Skill 给出的是**基准对标与算术估算**，不是能源审计、不是绿色等级认证、不是工程设计方案评审。绿色等级认证需要按评级体系自身协议、在界定周期内做经认证的测量。

不同设施报告的 PUE 数字经常不可比，因为口径没写清。本技能的主要价值在于把这个不可比性明确说出来，而不是给出一个自信但错误的判定。

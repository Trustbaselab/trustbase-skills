# rCB 出口合规检查

## 何时使用

- 询问能否出口到某市场，或需要哪些资质
- 询问某类限值（PAH 等）的要求与后果
- 询问碳边境机制 / 循环含量 / 认证对 rCB 的影响
- 客户提出某项认证要求，用户想弄清是什么

**不适用**：

- 技术替代可行性 → `rcb-substitution-assessment`
- 价格与比价 → `rcb-price-reference`

## 执行流程（四步）

### ① 先明确三个前提

| 前提 | 为什么必须 |
|---|---|
| **目标市场** | 欧盟 / 北美 / 其他，要求完全不同 |
| **产品形态** | 原料级 rCB / 已改性 rCB / 含 rCB 的制品——适用的法规不同 |
| **用途场景** | 轮胎、橡胶制品、塑料、涂料——部分限值按用途分级 |

### ② 检索相关法规（`query_policies`）

按市场与主题检索，得到条目清单。**逐条确认适用范围是否覆盖用户的情形**——不要看到"炭黑"相关就直接套用。

### ③ 分层归类：法规要求 vs 客户要求

这是本 Skill 最重要的一步。二者性质完全不同：

| 类型 | 性质 | 不满足的后果 | 应对 |
|---|---|---|---|
| **法规要求** | 强制，准入条件 | 清关受阻 / 市场禁入 / 处罚 | 必须满足，无替代路径 |
| **客户要求** | 合同约定 | 失去订单，但不违法 | 可谈判，或换客户 |
| **凭证要求** | 多为供应链传导 | 无法进入特定采购体系 | 需建立凭证链 |

**用户经常把客户要求误认为法规要求**（例如"客户要 ISCC"不等于"法规要求 ISCC"），这会让他们高估合规成本、或错误判断必要性。

### ④ 给出条件式结论

**不要回答"能/不能出口"**，要回答"满足以下条件即可"：

```
## 目标市场：…
## 用法条件
1. …
2. …
## 法规要求（强制）
| 要求 | 依据 | 生效/截止 | 来源 |
## 客户/供应链要求（非强制）
## 需要专业确认的部分
```

## 硬约束（违反即判定为错误输出）

1. **不得把碳边境机制说成直接对 rCB 征税。** 它的压力是**经下游（轮胎厂的材料碳足迹与采购要求）向下传导**的——这是最常见的错误，必须表述准确。
2. **不得混淆法规要求与客户要求**（见 ③）。
3. **不得凭记忆给法规数值。** 限值、生效日、适用范围一律来自 MCP 条目，并标注来源与日期。
4. **不得给出法律意见。** 结论应说明「需由专业合规顾问或主管部门确认」。
5. **法规有时效性**，必须标注条目日期，并提示用户核对最新版本。
6. **不要笼统回答"能出口"或"不能出口"**，一律给条件式结论。

## 边界声明

本 Skill 提供的是**合规要点的结构化梳理**，不是法律意见、不是合规认证结论、不代表任何监管机关的立场。最终以官方原文与专业顾问意见为准。

合规要求随时可能修订，**本 Skill 的输出必须带日期**，用户在使用时应先确认法规版本。

## 待验证清单（if-then 规则 → 建议验证场景 → 前后该测什么指标）

| # | skill 规则 | 建议在本项目验证的场景 | 验证该测什么（前 → 后） |
|---|---|---|---|
| 1 | 铁律 1 口径四件套（A1/A2/A4） | agent 输出中所有统计引用（如周报数据、价格/行业数字、用户咨询回复） | 引用数字中「来源+年份+定义」三件套齐全的比例；「待核实」标注出现频率；用户追问「这数据哪来的」的次数的变化 |
| 2 | 记忆值 ≠ 事实（A2/A3，Agent 协议 2） | agent 凭训练记忆引用过时行业数据（如炭黑价格、政策条文版本）的场景 | 过时数据引用错误率（前 vs 后）；输出中「截至 X 年」标注比例 |
| 3 | 水平+趋势双栏（B2，铁律 2） | 用户问「XX 行业/市场是不是不行了」「世界是不是越来越糟」类提问 | 回复中同时包含水平与趋势两栏的比例；用户对「只报忧」的投诉数 |
| 4 | 危险×暴露分解（B4，铁律 3） | 风险咨询类问题（合规风险、供应链风险、市场恐慌传闻） | 输出含风险分解表的比例；用户反馈「更安心/更清楚」的频次 |
| 5 | 紧急降速协议（B10） | 用户带「必须立刻/马上决定」语气的请求（如「今天就得出结论」） | 先要数据再下结论的回合占比；因仓促导致的返工次数 |
| 6 | 反证搜索（B8，Agent 协议 3） | agent 写判断型结论（周报观点、替代评估结论）时 | 结论附带反证/替代指标的占比；被用户指出「只说了一面」的次数 |
| 7 | 系统归因（B9） | 失败复盘、事故/错误归因报告（如自动化线失败归因） | 归因中出现「结构/激励/信息/历史」因素的报告占比；「都怪 XX」单点归因的占比变化 |
| 8 | 二分法替换（B1） | 用户或文档使用「发达国家/发展中国家」「穷/富」等标签的场合 | 输出中使用分级/分布替代二元标签的比例 |
| 9 | 勘误即行动（A6） | agent 发现自身引用错误的处置方式 | 显式勘误次数 / 静默修改次数（人工抽查记录） |
| 10 | 情绪词清单（C3） | 周报/专栏/用户沟通文本 | 文本中戏剧化措辞（崩盘/毁灭/完蛋等）出现频率（前 vs 后） |

**验证方法建议**：由 lead 从工作区既有回执/报告存档中抽取基线样本（如最近 N 轮输出），统计上述指标，再在本 skill 上线后的后续轮次中做对比；口径与采样规则由 lead 定义并记录。

## 数据口径与诚实边界

1. **本文件目前不含任何实测数据**：以上全部为候选方案，不构成「已验证」的声明；skill 的 SKILL.md 与引用文件中也未宣称本项目已有验证证据。
2. **规则与验证的区分**：书中证据锚（GMS 2017、13 题、官方勘误页等）是「书内证据」，已在 `references/factfulness-book.md` 标注来源与局限；本项目的验证状态是另一回事，两者不得混用。
3. **书中数据会过时**：本书数据截至 2016–2017（出版 2018）；2019 年后疫情、民主质量、预期寿命等趋势已变化，本项目任何未来验证都应使用当年代口径，不与书中数字直接对比。
4. **归因边界**：未来若记录真实案例，应用与规则之间是「事后映射」而非对照实验，表述应为「本项目的应用案例」而非「因果证明」（与 `bandwidth-and-deep-work/references/evidence.md` 的口径纪律一致）。

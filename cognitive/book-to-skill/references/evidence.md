# 实证记录：这个方法在我们的项目里产出了 5 个上线 skill（evidence）

> 用途：当 `book-to-skill` 需要「这不是空谈方法论，而是被真实验证过的流程」的证据时加载。
> 口径来源：`Trustbaselab/trustbase-skills` 仓库实际产出（2026-10-18）。

---

## 场景

一个 AI 驱动的项目组（Trustbase Lab），需要把有思想高度的书转成 agent 可执行规则，
用于「可信数据」业务的方法论支撑。

---

## 证据 1 · 方法本身产出了 5 个上线 skill

| 项 | 内容 |
|---|---|
| **问题** | 市面上的 book-to-skill 多为「读书笔记」式总结，无验证、无质量闸门、无法复用 |
| **本方法的概念** | **七步 SOP + 三重质量闸门 + 四条诚实边界** |
| **具体做法** | 先做 1 本（《稀缺》+《深度工作》），跑通流程；再用同一流程做 4 本（《事实》《思考，快与慢》《噪声》《系统之美》） |
| **量化结果（前 → 后）** | **1 个 skill（1 本书）→ 5 个 skill（6 本书）**；**全部通过格式/诚实边界/版权三项验收**；**4 本新 skill 在同一批次内产出** |

> 对应本方法原理：「能力是通用的，标准是专项的」—— 同一 SOP 可套不同书，
> 但每本都必须过同一套闸门。

## 证据 2 · 质量闸门拦下了真实问题

| 项 | 内容 |
|---|---|
| **问题** | 第一版 `bandwidth-and-deep-work` 缺 `evidence.md` 与 `METHOD.md` |
| **本方法的概念** | **闸门 3（交付检查清单）** |
| **具体做法** | 用检查清单验收，发现缺失 → 下发补丁规格 v1 → 工作组补齐 |
| **量化结果（前 → 后）** | **缺 2 个文件 → 补齐 `evidence.md`（5.1KB）**；**且该文件主动写出两处数据口径不一致（10,612 行 vs 7,451 行），未合并加工** |

> 对应本方法原理：**检查清单不靠人记** —— 缺什么，清单上会显示。

## 证据 3 · 方法被固化成可复制的模板

| 项 | 内容 |
|---|---|
| **问题** | 第一批 skill 的做法是「口口相传」，无法交给别人复现 |
| **本方法的概念** | **把流程变成工具** |
| **具体做法** | 抽出四个模板：选书打分表 · SKILL 模板 · evidence 模板 · 交付检查清单；写 `METHOD.md` 第九节「可行性办法」 |
| **量化结果（前 → 后）** | **0 个可复用模板 → 4 个模板 + 1 份 SOP**；**任何人拿到模板即可按七步产出新 skill** |

> 对应本方法原理：**和数据层同构** —— 事实包靠 `build_pack.py` 复用，书→skill 靠这四个模板复用。

---

## 数据口径与诚实边界

1. **skill 数量（5 个）为仓库实际文件计数（`cognitive/*/SKILL.md`），可复核。**
2. **「4 本在同一批次内产出」是时间事实（2026-10-18 21:00 前后到货），不代表标准化的因果效应。**
3. **本方法**尚未被外部第三方独立使用验证** —— 「任何人拿到模板即可产出」目前是设计目标，不是已证明的事实。**
4. **归因限制**：七步 SOP 与最终产物质量之间的对应是**事后整理**（先做出 skill，后归纳方法），
   不是对照实验 —— 引用时表述为「本项目的验证案例」，而非「因果证明」。

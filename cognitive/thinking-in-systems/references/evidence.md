## 真实应用案例

### 案例 A · 任务单存量的「无流出」问题（2026-10-18）

| 项 | 内容 |
|---|---|
| **问题** | 任务单 `DSH-INBOX.md` 只进不出：所有历史任务与回执持续追加到同一文件，文件膨胀到 **565.6KB / ≈141,500 tokens**（`trustbase/REVIEW-TASK-TRACKING.md` 实测；行数口径存在两个历史记录：BRIEF 10,612 行 / REVIEW 7,451 行）。执行方每轮要读它找「当前任务」→ token 浪费 + 误判风险 |
| **书里哪个概念** | **存量（stock）与流量（flow）**：存量的流入（追加任务）远大于流出（无归档）时，存量无界增长；**调节回路缺失**：没有阈值、没有反馈机制把存量压回边界 |
| **具体做法** | 给系统加**流出**：按月/按任务归档到 `_archive/`，`DSH-INBOX.md` 只保留当前队列 + 最近 3 轮；相当于给存量加调节回路，把「只进不出」改成「有进有出」 |
| **量化结果（前 → 后）** | 文件 **565.6KB → 26.8KB（-95%）**；`STATUS: PENDING` **67 → 2**；执行方每轮读取 ≈141K → **5.6K tokens（-96%）**；状态查询 2–3 分钟 → 5 秒（同项目另一项改造，见 `bandwidth-and-deep-work/references/evidence.md`） |

> 诚实边界：①这是**事后映射**（先有归档改造，后有概念归因），不是对照实验；②数据来自补丁规格与 REVIEW 自查，行数口径差异已在 `factfulness/references/evidence.md` 记录；③「-96% tokens」为估算口径（按读取比例推算），非精确计量。

## 数据口径与诚实边界

1. 本文件**不含任何测量结果**：全部为候选方案，数字列均为「该测什么」，不是「测到了什么」。
2. 未来补案例时的口径要求（沿用 `bandwidth-and-deep-work` 的做法）：问题 → 用了书中哪个概念 → 具体做法 → 量化结果（前 → 后）；数字可复算（文件路径、口径、测量方法），并区分「实测」与「估算」。
3. 应用归因限制：系统结构的改变常与人员、时机、外部条件混在一起，事后归因为「书的概念生效」只能是**事后映射**，不是对照实验；引用时表述为「本项目的验证案例」而非「因果证明」。
4. 书中数字（电表 30%、TRI 40%、99% 信息故障）是作者转述口径，不构成本 skill 的验证数据，禁止混入本项目 evidence。
5. 深度指标（范式层、目标层）难以量化：若未来涉及，只做定性前后对照（文本、决策记录），并明确标注「定性观察」。

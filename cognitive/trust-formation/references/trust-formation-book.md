## 一句话论点

信任正从「机构信任」转向「分布式信任」：人们不再因为你是大机构而信你，而是因为你能被验证才信你。信任必须从声称（claim）变成可验证（verifiable）。

## 核心论证链（紧凑流程）

1. 信任是合作的基础设施：无信任则无交易与协作。
2. 机构信任崩塌：Edelman 2017 以「全球信任崩塌」为题报告机构信任的历史性下滑。
3. 分布式信任兴起：平台让陌生人互信成为可能，信任流向改变（trust shift）。
4. 每次新交互都是一次信任跃迁（trust leap）：无先验证据地冒险尝试新事物。
5. 平台的工作是降低跃迁风险：身份/评价/托管/保险等信任信号。
6. 关键辨析：信任 ≠ 信心（confidence 基于过去可预测），信任 ≠ 风险（risk 可概率化）。
7. 结论：数字时代信任设计 = 把声明翻译成可检验陈述（能力/可靠/正直/透明 × 可核验事实）。

## 概念词典（要点版）

| 概念 | 精确定义 | 常见误解 |
|---|---|---|
| trust 信任 | 与未知之间的自信关系（"a confident relationship with the unknown"，页次**待核实**）；需脆弱性与选择 | ≠ 好感/认可；≠ 高置信度 |
| confidence 信心 | 基于过去经验可预测性的把握感；被动、不需脆弱性 | ≠ 信任；信任面向未知，信心面向已知 |
| risk 风险 | 可概率化、可对冲的不确定性；不需要关系 | ≠ 信任；「降低风险 = 建立信任」是作者点名的行业通病 |
| institutional trust 机构信任 | 对政府/媒体/银行/大企业的授权式信任 | 衰落 ≠ 归零；信任总量未必减少，是流向改变 |
| distributed trust 分布式信任 | 陌生人之间经由技术与社区信号流动的信任（评价/身份/担保/算法声誉） | ≠ 天然更可靠（刷评/假身份/算法偏见）；≠ 区块链（区块链只是一类载体） |
| trust shift 信任转移 | 信任对象与流动方向从机构转移到平台/算法/陌生人网络 | 是并存混合，不是增量替换 |
| trust leap 信任跃迁 | 无先验证据时冒险尝试新事物/全新方式（精确原文**待核实**） | ≠ 盲目轻信；是受信号引导的冒险，平台垫付部分风险 |
| trust stack 信任堆栈 | 市场情境下分层：①信这个主意 → ②信这个平台 → ③信对面的人（2021 年 Ghent 论文引 "climbing the trust stack (Botsman, 2017)"） | 层数随语境变（AI 场景可加「信这个算法」层）；各层独立，信平台≠信个体 |
| trust signals 信任信号 | 身份核验/评价评分/托管支付/保险/社交图谱等降低跃迁风险的线索 | 信号可造假、可过载；关键是**可核验**；评分系统降的是风险感，≠建立信任关系 |
| dark side 黑暗面 | 信任被操纵：刷评、假身份、机器人、把信任货币化却回避问责的平台 | 分布式信任并非天然向善，作者明确警示信任可被武器化 |
| competence 能力 | 四要素之一：「你做得到吗？」（兑现承诺的技术与执行能力） | ≠ 资质头衔；要用可核验交付事实证明（工具数/记录数/覆盖域） |
| reliability 可靠 | 四要素之一：「你每次都做得到吗？」（时间上的一致与可重复） | ≠ 零错误；需时间序列证据（连续抽样/历史日志），单点表现不算 |
| integrity 正直 | 四要素之一：「利益冲突时你会不会牺牲我？」 | 含**主动披露不足**（缺口/边界/免责）；犯错≠不正直，区别在是否主动纠正留痕 |
| transparency 透明 | 四要素之一：「我能验证吗？」（过程与证据可见可查可复核） | 透明≠信任（作者 2018 CIPD 演讲）；「公开但不可查」只是展示 |
| verifiability 可验证性 | 第三方可独立复核陈述：稳定 ID + 来源 URL + 时点 as_of + 口径 + 回查路径 | 是**表述纪律**问题，不只是技术问题；可验证是信任的新形态，不是替代 |
| accountability record 问责记录集 | 逐条可回查 + 纠错留痕的记录集（本项目 S-3 用语，非书中术语） | ≠ 数据库（数据库只是能查的库）；≠ 量越大越好，重点是问责链完整 |
| S-1 四问 | 谁担保 · 哪一手的 · 置信度几级 · 能否回查（本项目 S-1 表述纪律） | 是项目纪律，非书中术语；「来源大」≠够，要落到可打开的 URL |
| A/B/C 置信度 | A=官方备案/公告 · B=公司声明/权威媒体 · C=未验证；verified==A；由来源类型决定，不由编辑偏好决定 | A 指**来源等级**，≠ 内容必对；数字仍可被口径/时点问题击穿 |

> ⚠️ 四要素（competence/reliability/integrity/transparency）的**书中精确出处待核实**；本 skill 只称「基于本书理念的翻译」，不称「书中原文」。书中可核证的核心框架是 trust/confidence 辨析、trust leap、distributed trust、trust stack。

## 证据锚（案例/数据浓缩版，每条含出处+局限）

1. **Airbnb：陌生人信任规模化**（本书主干案例）。平台用身份核验、双向评价、照片、支付托管降低跃迁风险。局限：刷评/报复性差评扭曲评价系统。
2. **Uber：把命交给陌生人**（本书）。双向评分+轨迹+支付托管替代牌照信任。局限：事故与审核丑闻显示「平台责任」是信任薄弱层。
3. **BlaBlaCar：拼车的「Bla」因子**（本书）。社交相似性与透明度降低共乘跃迁阻力。局限：文化依赖性强。
4. **比特币/区块链：无机构担保的价值转移**（本书）。信任转移到代码与账本。局限：2017 年后价格/能源/监管争议部分证伪乐观叙事。
5. **Edelman 2017 "Global Implosion of Trust"**（edelman.com 官方页）。机构信任「最大跌幅」叙事。局限：方法学争议——「知情公众」样本、单题测量、发布方为公关公司。
6. **CIPD 2018 主题演讲：「透明不是建立信任的答案」**（peoplemanagement.co.uk 报道）。透明须配问责与能力。局限：报道转述，非论文。
7. **CSPAN2 2017-12-23 读书会**（archive.org 录像）。作者口述版论点校准源。局限：口语转写精度有限。
8. **Trustbase Lab 产品事实**（项目内实测 2026-10-18，trustbase/TRUST-FOUR-ELEMENTS.md + MCP 概览）：59 工具 / 2,738 记录 / 6 域；抽样 100 条基准 89% A 级；8 条数据缺口如实披露；193/193 回查 URL 实测 200。局限：**事实映射，非因果验证**。

## 可操作原则（书中证据推出，已入 SKILL.md 处方库）

> 处方编号 A=能力 · B=可靠 · C=正直 · D=透明 · E=信任机制；完整 if-then 见 SKILL.md。

- A1–A3 能力：数字+口径+入口；内部统计附测量方法；声明收窄到实际覆盖。
- B1–B3 可靠：数字必带 A/B/C 与 as_of；不可验证时降确定性表述；抽样比例必须写样本量。
- C1–C3 正直：缺数据明说缺口；纠错主动留痕；利益冲突主动披露。
- D1–D3 透明：承诺必须附问责条款；验证入口用稳定 ID+快照；「全部通过」带测试方法与数量。
- E1–E3 信任机制：先辨析信任/信心/风险再谈分布式信任；信任堆栈分层评估外部平台；只保留可复核的信任信号。

## 批评与边界（红线列表）

1. 四要素框架出处**待核实**——引用时不称「书中原文」。
2. 技术乌托邦批评：平台信任可被操纵；「信任机器」叙事已部分证伪。
3. Edelman 数据引用必须注口径与发布方立场（与 `factfulness` 数据口径四件套交叉）。
4. 透明≠信任；信任≠信心；降风险≠建信任——三条辨析是本 skill 的防误用护栏。
5. 「信任跃迁」不是用户担责的借口；设计者的责任是降低跃迁风险。
6. 对外文案不用「信任层」一词（项目 S-1 决策）；不用任何自夸词（值得信赖/权威/领先/顶尖/独家……）。
7. 福山论点只作底层引用：社会信任降低交易成本；不采用其文化二分学（被批文化本质主义）。
8. 证据状态纪律：本 skill 全部「待验证」；产品事实是映射不是验证。
9. 四要素不全时的处理：任一要素无事实支撑时，声明框架该格写「待验证」并留空，不写愿景句或形容词。
10. 本书是 2017 年语境：平台监管丑闻、算法信任危机在此后深化；规则使用时以「可验证」原则为准，不照搬书中平台案例的乐观结论。

## 对 agent 工作的映射（10 条）

1. 输出事实断言 → 附可回查路径（record ID + source URL + as_of），否则标「未验证」。
2. 写文案前 → 过自夸词黑名单自查，命中即改写为「事实+入口」。
3. 被要求「数字差不多就行」→ 写「约」或「待核实」，不把估算冒充实测。
4. 发现此前输出有误 → 发纠正并说明原因，不静默重写。
5. 被要求「证明我们可信」→ 输出四要素声明框架（模板 1），每格附验证入口。
6. 引用信任调查（Edelman 等）→ 表述为「该调查显示」并注口径与方法学争议。
7. 数据口径核查 → 转 `factfulness`；结论过度自信复核 → 转 `thinking-fast-and-slow`；「你怎么确定」类理解校准 → 转 `knowledge-illusion`；注意力/多任务 → 转 `bandwidth-and-deep-work`。
8. 评估外部平台/来源 → 信任堆栈三层出「信任核查卡」，缺层即风险点。
9. 设计信任信号 → 只保留能被第三方复核的信号。
10. 缺数据 → 明说「我们没有这项数据」并说明缺口，不用相近数据替代。

## 福山底层引用小节（引用层，非本 skill 核心框架）

- **论点**：国家的繁荣与竞争力由一种普遍文化特征决定——社会固有的信任程度（社会资本）。高信任社会拥有「自发社交性」（spontaneous sociability），人们能在家庭之外自发结成大型经济组织；**社会信任降低交易成本**。低信任社会（家族主义传统深厚者）经济组织难以超越家族规模。
- **出处**：Francis Fukuyama, *Trust: The Social Virtues and the Creation of Prosperity*, Free Press, 1995；中译见上表。
- **与博茨曼数字信任的关系**：福山回答「信任**为什么**值钱」（社会资本 → 交易成本 → 经济组织规模），博茨曼回答「信任**现在流向哪里、如何重建**」（机构 → 分布式、声称 → 可验证）。二者互补不竞争：福山框架解释 Trustbase Lab 业务的经济学理由（降低产业信息交易成本），博茨曼框架解释产品形态（可回查的问责记录集）。
- **纪律**：福山内容只出现在 references（本文件与研究笔记 §4b），不进入 SKILL.md 规则主体；不采用其「高信任/低信任文化」二分学（被批评为文化本质主义）。
